Section 1 — Problem Statement

1.1  The Human Cost
Road accidents are one of the leading causes of fatalities in India, resulting in over 1,50,000 deaths annually. Medical research consistently shows that nearly 50% of these deaths are preventable if emergency medical assistance reaches victims within the Golden Hour — the critical 60-minute window following trauma when intervention saves lives.

The tragedy is not a lack of emergency services. It is a systemic delay in reaching them. In India’s highway corridors and urban outskirts, accidents often occur in locations with no witnesses, no functional lighting, poor cellular coverage, and high traffic congestion. Victims lie unattended for critical minutes — sometimes hours — while the clock on their survival runs down.

1.2  Why current systems fail
Detection depends on humans: accidents must be seen, recognised, and reported by a bystander before any response begins
Reporting is unreliable: panic, language barriers, and poor connectivity cause delayed or inaccurate emergency calls
Dispatch is sequential: call centre receives report, verifies, contacts ambulance, ambulance navigates traffic — each step adds minutes
No autonomous first responder exists that can reach a victim, assess severity, provide guidance, and dispatch help simultaneously
Golden Hour violations are the norm, not the exception, on Indian national highways

1.3  Problem Statement — One Line
How do we build an autonomous aerial first-responder that detects road accidents without human notification, assesses victim severity, provides immediate on-site first-aid guidance, and dispatches emergency services — all within 90 seconds, without any human trigger?

Section 2 — Proposed Solution: RAVEN

2.1  Solution Overview
RAVEN — Rapid Autonomous Victim Emergency Network — is an AI-powered autonomous drone-based emergency first-responder system. It continuously patrols accident-prone highway corridors and urban roads, autonomously detects road accidents using computer vision, assesses victim conditions through AI triage, provides immediate voice-guided first-aid assistance, deploys emergency supplies via a servo-triggered payload mechanism, and simultaneously dispatches alerts to ambulances, hospitals, and traffic authorities — without any human trigger or intervention.

The entire detect-to-dispatch pipeline completes in under 90 seconds. RAVEN does not replace ambulances. It fills the critical gap between when an accident happens and when human responders arrive — the window where lives are currently being lost.

2.2  MVP strategy for Round 1
For Round 1 submission, RAVEN’s drone is mounted on a static stand. The full AI pipeline — detection, triage, voice guidance, payload release, dispatch, and dashboard — runs live on real hardware. The drone does not need to fly autonomously to demonstrate the intelligence layer. Judges evaluate the AI agent, not the flight controller. Autonomous flight is the Round 2 upgrade.

2.3  End-to-end autonomous workflow
A camera feed enters the Raspberry Pi 4 / Jetson Nano. YOLOv8 Nano processes frames in real time, detecting collisions, overturned vehicles, victims lying on the road, smoke, and fire. On detection, the 7-state autonomous agent FSM activates. The triage agent counts victims, estimates posture and injury severity, and computes a 0–100 severity score. The decision engine selects the response tier, triggers gTTS voice guidance through the speaker, commands the MG996R servo to release the first-aid payload kit, sends GPS coordinates and incident data to the FastAPI backend, fires an SMS alert via Africa’s Talking, and streams live data to the React operator dashboard — all autonomously.


Section 3 — System Architecture

RAVEN’s architecture is structured into six layers. The autonomous agent layer (Layer 3) is the central intelligence — it receives perception data, makes all decisions, and coordinates every downstream action without human input.

L1
Perceive
Camera: OV5647 Pi Camera or USB webcam, 1080p, 30 fps continuous capture
Thermal: MLX90614 IR sensor — detects fire, heat signatures from victims
GPS: Neo-6M / M8N module — continuous location fix, logged at 1 Hz
Ultrasonic: HC-SR04 — obstacle detection for future autonomous navigation
↓
L2
Detect
YOLOv8 Nano: Real-time object detection — collision, overturned vehicle, victim lying, smoke, fire
OpenCV: HSV-based fire/smoke mask, frame pre-processing, ROI extraction
Victim counting: Bounding box enumeration per detection frame, temporal smoothing
Posture estimation: Bounding box aspect ratio heuristic to classify standing vs lying down
↓
L3
Autonomous Agent FSM
7-state FSM: PATROL → DETECT → ASSESS → COMMUNICATE → DEPLOY → DISPATCH → RELAY
Severity scoring: 0–100 composite score: victim count (40%), posture (30%), fire/smoke (20%), vehicle damage (10%)
Decision engine: Maps severity score to response tier: Minor (<30), Serious (31–70), Critical (>70)
Action selection: Autonomously selects language, payload trigger, dispatch priority, alert urgency
Confidence gate: Detection confidence <0.70 → agent continues patrolling, does not trigger false alarm
↓
L4
Communicate & Act
Voice guidance: gTTS generates contextual first-aid audio in English, Hindi, Tamil. Speaker plays on arrival.
LLM guidance: Ollama + Mistral 7B (local, offline) generates adaptive scene-specific instructions
Payload release: MG996R servo releases kit containing bandages, tourniquet, gauze, emergency blanket
SMS alert: Africa’s Talking API sends GPS, victim count, severity score to ambulance and hospital
Webhook: FastAPI endpoint pushes structured incident JSON to dashboard in real time
↓
L5
Hardware Body
Flight computer: Raspberry Pi 4 (4 GB) — primary AI inference and agent runtime
Drone frame: 450mm quadcopter frame or F450 — mounts all payload and electronics
Custom PCB: KiCad-designed sensor integration board: GPS + IR + ultrasonic + servo headers
Power: 3S/4S LiPo battery, PDB, XT60 connectors, 5V BEC for RPi and peripherals
CAD payload bay: FreeCAD-designed first-aid kit housing with servo-actuated release latch, 3D-printed PETG
↓
L6
Dashboard & Monitor
React frontend: Real-time operator interface — live drone GPS, incident feed, severity score, victim count
Leaflet.js + OSM: Open-source map tiles — drone position pin, incident location, ambulance ETA overlay
WebSocket: FastAPI WebSocket pushes live updates to dashboard without polling
PostgreSQL: Incident log database — stores all accident records, timestamps, severity, outcomes
Incident report: Auto-generated PDF report: GPS, victim count, severity, actions taken, response time


Section 4 — Autonomous Agent: 7-State FSM

4.1  Severity scoring formula
Severity Score = (victim_count_score x 0.40) + (posture_score x 0.30) + (fire_smoke_score x 0.20) + (vehicle_damage_score x 0.10)   |   Score 0–30 = Minor · 31–70 = Serious · 71–100 = Critical

4.2  Confidence gate — false alarm prevention
The agent only transitions from PATROL to DETECT if YOLOv8 detection confidence exceeds 0.70 AND the detection persists across 3 consecutive frames (600ms at 5fps inference). Single-frame detections, low-confidence blips, and environmental false triggers (parked vehicles, shadows) are filtered out. This is the mechanism that makes RAVEN deployable on real roads without flooding emergency services with false alarms.


Section 5 — Module Implementation Details

M1
Accident Detection Module
P
Purpose: Detect road accidents automatically and reliably in real-time video.
T
Technologies: YOLOv8 Nano (Ultralytics, AGPL v3), OpenCV (Apache 2.0), Python 3.10
W
How it works: Camera streams frames to YOLOv8 Nano running on RPi 4. Model detects: collided vehicles, overturned vehicles, victims on road, smoke, fire. Custom fine-tuned on accident dataset (COCO + Roboflow accident images). Inference at 5–8 fps on RPi 4. Confidence gate at 0.70 prevents false positives.

M2
Victim Assessment & AI Triage
P
Purpose: Estimate incident severity to determine autonomous response priority.
T
Technologies: Python, NumPy, OpenCV, custom severity scoring logic
W
How it works: Victim count from YOLOv8 bounding boxes. Posture classified by bounding box aspect ratio (height > width = standing, width > height = lying). Fire/smoke detected by HSV colour mask (red/orange/grey ranges). Vehicle damage estimated by detection class. All scores combined into 0–100 severity index.

M3
Autonomous Decision Engine
P
Purpose: Run the 7-state FSM and coordinate all autonomous actions.
T
Technologies: Python state machine (transitions library, MIT), FastAPI (MIT), asyncio
W
How it works: Python FSM library manages state transitions. Each state has entry/exit actions and guard conditions. The engine runs as an async event loop on RPi 4, processing perception events and issuing action commands. All decisions logged with timestamp for post-incident review.

M4
Voice Guidance System
P
Purpose: Provide first-aid instructions to victims and bystanders before medical teams arrive.
T
Technologies: gTTS (MIT), Ollama + Mistral 7B (MIT/Apache 2.0), speaker module, pygame (LGPL)
W
How it works: Severity score and victim context sent to Mistral 7B via Ollama (runs fully offline on RPi 4 / Jetson Nano). LLM generates scene-specific first-aid instructions. gTTS converts to audio in English, Hindi, or Tamil based on GPS location zone. pygame plays audio through speaker. Example: ‘Two victims detected. Do not move the injured. Apply pressure to visible wounds. Emergency services notified. Help is 8 minutes away.’

M5
First-Aid Payload Deployment
P
Purpose: Deliver emergency medical supplies immediately to the accident scene.
T
Technologies: MG996R servo, RPi GPIO, FreeCAD-designed payload bay (PETG 3D print)
W
How it works: Payload bay designed in FreeCAD and 3D-printed in PETG. Contains: bandages, tourniquet, gauze pads, emergency blanket, whistle. MG996R servo controlled via RPi GPIO PWM. Agent sends servo release command on entering DEPLOY state. Drop zone calculated from camera depth estimation.

M6
Emergency Dispatch System
P
Purpose: Autonomously notify emergency services with structured incident data.
T
Technologies: FastAPI (MIT), Africa’s Talking SMS API (free tier), Python httpx (BSD)
W
How it works: FastAPI endpoint receives POST from agent with: GPS coordinates, victim count, severity score, timestamp, live feed URL. Africa’s Talking SMS sends structured alert to registered ambulance and hospital numbers. All dispatch events logged in PostgreSQL. Webhook also available for future integration with 108 helpline systems.

M7
Operator Dashboard
P
Purpose: Provide real-time situational awareness to emergency operators.
T
Technologies: React (MIT), Leaflet.js + OpenStreetMap (BSD-2 / ODbL), WebSocket, FastAPI, PostgreSQL
W
How it works: React frontend connects to FastAPI WebSocket for live updates. Leaflet.js renders drone GPS position and incident location on OSM map. Dashboard panels: live video feed, severity score, victim count, dispatch status, ambulance ETA, incident history. All data persisted in PostgreSQL for post-incident analytics.


Section 6 — PCB Design Plan

One custom PCB is designed in KiCad — the RAVEN sensor integration board. It connects the GPS module, IR thermal sensor, ultrasonic sensors, servo, speaker amplifier, and status LEDs to the Raspberry Pi 4 via a single clean interface. Physical fabrication is not required for Round 1 — Gerber files and schematic PDF are submitted in the GitHub repo.
